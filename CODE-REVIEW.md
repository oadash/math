# Код-ревью Math Adventure

Дата: 2026-05-03

Ниже — ревью по текущему состоянию проекта. Пункты сгруппированы по приоритету: что чинить сразу, что планировать как важный техдолг, что оставить как улучшения.

## P0: починить сразу

### 1. `/en/` redirect loop

Статус: исправлено в `b118b5f`.

Причина была в `server/routes/practice.js`: Express без strict routing матчел `/en/` на роут `GET /en`, который редиректил на `/en/` снова.

Текущий фикс делает редирект `/en` точным через проверку `req.path !== '/en'`, чтобы `/en/` доходил до `renderLandingPage('en')`.

### 2. Pin locked topic позволяет обойти прогрессию

В `POST /api/topic/pin` сейчас достаточно, чтобы тема существовала в `user_topic_state`; состояние `locked` явно не запрещается. Это позволяет закрепить залоченную тему и затем получать задачи вне prerequisite-графа.

Риск:

- ребенок может начать с поздних тем, минуя progression;
- ответы по таким темам попадут в `answers` и родительскую статистику;
- тест `POST /api/topic/pin allows locked topic` закрепляет это поведение как ожидаемое.

Решение:

- если это не продуктовая фича, запретить pin для `state === 'locked'` с `403`;
- обновить тест: ожидать `403` для locked;
- если свободная практика по locked темам нужна, оформить это явно отдельным режимом, а не через тот же pin.

### 3. Restore по shortcode требует rate limit

`POST /api/users/restore` фактически является входом без пароля. Код с коротким числовым суффиксом можно подбирать, особенно если известно имя ребенка.

Минимум:

- rate limit на `/api/users/restore`, например 10 попыток в час на IP;
- нормализация на сервере: `trim().toUpperCase()`;
- логирование неудачных restore-попыток;
- рассмотреть более длинный суффикс, например 6 цифр.

### 4. `/health` говорит `ok: true` до завершения миграций

Миграции запускаются после `listen`, поэтому первые запросы могут попасть в приложение до применения схемы и прогрева topic cache. При этом `/health` уже отвечает успешно.

Решение:

- ввести readiness-флаг миграций;
- `/health` или отдельный `/health/ready` должен возвращать `ready: false` до окончания migrate + topic cache warmup;
- Railway healthcheck можно оставить быстрым, но он не должен маскировать неготовую БД.

## P1: важные проблемы

### 5. Decimal/fraction темы маскируют ограничение формата ответа

`decimals_add_sub`, `decimals_multiply`, часть fraction-тем тренируют не совсем то, что обещает название. Например, вместо ответа `7.0` ребенок должен дать целое число в десятых долях.

Решение:

- для decimal-тем использовать `stringAnswer`, как для дробей;
- либо переименовать/переформулировать темы как задачи на разрядность и представление чисел.

### 6. Генераторы используют fallback-задачи и рекурсию

В ряде генераторов при неудачном подборе параметров возвращается фиксированный fallback. В `linear_equation_3` есть рекурсивный self-call без внешнего счетчика.

Риск маловероятный, но это делает поведение недетерминированным и скрывает сломанные constraints.

Решение:

- заменить рекурсивные retry на bounded loop;
- после исчерпания попыток бросать явную ошибку или возвращать fallback с `console.warn`;
- покрыть генераторы тестами на отсутствие fallback-повторов.

### 7. Дублирование `problemGenerator.js` и `problemGeneratorEn.js`

Логика генерации продублирована, отличаются в основном строки `display`. Тесты качества покрывают русскую версию, английская может разъехаться незаметно.

Решение:

- минимум: прогонять те же quality-тесты для `generateProblemEn`;
- лучше: вынести генерацию структурированных данных и форматировать `display` отдельно по языку.

### 8. Topic cache — глобальное состояние без TTL и межпроцессной инвалидации

Сейчас это приемлемо для одной реплики, но в будущем несколько реплик могут держать разные версии топиков после миграции/seed.

Решение:

- добавить комментарий про single-process assumption;
- рассмотреть TTL;
- в тестах лучше инжектить cache как dependency, вместо ручного `invalidateTopicCache()`.

### 9. SEO practice-страницы генерируют случайные примеры на каждый запрос

`renderPracticePage` вызывает генератор 5 раз на каждый GET, поэтому HTML одной и той же страницы меняется от запроса к запросу.

Риск:

- нестабильный HTML для поисковиков;
- хуже CDN caching;
- сложнее отлаживать SEO.

Решение:

- deterministic seed по `(slug, lang)`;
- либо кеш HTML/примеров в памяти на фиксированное время.

### 10. Client-side language redirect на лендинге

Сейчас redirect по browser language выполняется JS-ом на клиенте. Это лучше, чем ничего, но пользователь может увидеть flash RU-страницы, а crawler не обязан выполнять JS как обычный браузер.

Решение:

- делать серверный redirect по `Accept-Language` для `/` при пустом/внешнем referrer;
- JS оставить fallback-ом.

## P2: безопасность и эксплуатация

### 11. JWT dev fallback secret

Если публичный инстанс случайно запустится без `NODE_ENV=production`, будет использован известный `dev-only-jwt-secret-change-me`.

Решение:

- требовать `JWT_SECRET` всегда;
- для локальной разработки использовать `.env.example`, а не fallback в коде.

### 12. CORS `origin: true` + `credentials: true`

Сейчас Origin отражается назад. Для Bearer-токена это не сразу критично, но при появлении cookie auth получится опасная база для CSRF.

Решение:

- production whitelist: `https://trainmath.fyi`;
- dev whitelist: localhost ports.

### 13. `sitemap.xml` при недоступной БД

При `pool === null` sitemap отдает `503` и пустой XML. Лучше явно сообщать crawler-ам, что стоит зайти позже.

Решение:

- добавить `Retry-After: 300`;
- оставить `503`.

### 14. Docker image можно уменьшить multi-stage build-ом

Сейчас frontend/backend зависимости живут в одном образе. Multi-stage позволит оставить в runtime только сервер и `client/dist`.

Ожидаемый эффект: меньше образ, быстрее деплой, меньше attack surface.

## P3: мелочи и поддерживаемость

### 15. `division_simple` содержит запутанную защиту

`[n, d].includes(q)` после `q === d` фактически не добавляет смысла для `n === q`, потому что `n = d * q`, `d >= 2`.

Решение: оставить защиту, если она нужна для anti-trivial-аудита, но добавить комментарий.

### 16. JSDoc в `client/src/api.js`

JSDoc для `friendlyApiMessage` оказался перед `pinTopic`, из-за чего IDE может показывать неверную подсказку.

Решение: перенести/удалить лишний JSDoc.

### 17. Английский генератор не тестируется quality-тестами

Связано с дублированием генераторов, но можно починить отдельно: запускать один набор проверок для RU и EN.

### 18. `gradeMapping.js` и `seoMeta.js` дублируют grade mapping

Два источника правды для соответствия topic slug -> grade.

Решение:

- вынести общий mapping в один модуль;
- добавить тест на согласованность, если оставить две структуры.

### 19. API ошибки частично русские при EN UI

Клиент локализует часть ошибок, но серверные `message` в ряде мест на русском.

Решение:

- отдавать стабильный `error`/`code`;
- текст выбирать на клиенте через i18n.

### 20. `schema.sql` и `gen_random_uuid()`

Если окружение PostgreSQL требует `pgcrypto`, миграция может упасть.

Решение:

```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;
```

### 21. `parent.test.js` использует хардкод даты

Хардкод `2026-04-26T12:00:00.000Z` делает тест менее выразительным и привязанным к исторической дате.

Решение: вычислять дату от `Date.now()` или фиксировать fake timers.
